LaTeX resumes keep their source files as part of the document. The source determines the PDF's contents and formatting. The standard form editor and design controls do not synchronize with arbitrary LaTeX.

## Run the local application

Install Docker Desktop with Docker Compose. From the repository root, copy `.env.example` to `.env` if you do not already have an environment file. Configure these settings in `.env`:

```dotenv
APP_URL=http://localhost:3000
DATABASE_URL=postgresql://postgres:postgres@postgres:5432/postgres
AUTH_SECRET=replace-with-a-random-secret
LATEX_COMPILER_TOKEN=replace-with-a-different-random-secret-at-least-32-characters-long
```

Generate each secret separately, for example with `openssl rand -hex 32`. Keep the template's container hostnames for PostgreSQL, Redis, and SeaweedFS. Leave AI providers unconfigured when an external assistant will write the resume.

Start the application and compiler:

```sh
docker compose -f compose.yml -f compose.latex.yml up -d --build
```

Open `http://localhost:3000`, create your local account, and import your resume under Documents. The first build downloads the application dependencies and TeX packages. Subsequent compilations run without internet access in the compiler container.

The compiler is private to the application network and has no published host port. It runs without root privileges, shell escape, or application credentials. The container also limits memory, processes, output files, and compilation time. Do not expose the worker directly to the internet.

## Import and edit

Import a standalone `.tex` file, or download your Overleaf project as a source ZIP and import that ZIP. A `.txt` file containing `\documentclass` near its beginning is also recognized as LaTeX.

The editor offers:

- Syntax highlighting, project file selection, and main-document selection.
- Automatic saving through the existing resume store, plus Undo and Redo.
- Compile PDF, a PDF preview, and a compiler log when compilation fails.
- PDF checks for page count, the page target you supply, overfull boxes and extracted text.
- Download PDF, Download source ZIP, and individual file downloads.
- Read extracted text to check that the PDF's text can be recovered.
- The existing document menu, duplication, application links, and version history.

Drag the divider between the source and PDF to resize the panes. Focus the divider and use arrow keys to adjust it, or press Enter or double-click to reset the split. The browser remembers the chosen size. Source highlighting, selection, and the cursor follow the app's light or dark appearance.

Use resume folders, company research, and the compact related-resume/job index to reuse previous work. See [Organize resumes and company research](./organizing-resumes.mdx) for the website controls, MCP tools, and tailoring workflow.

The [Chrome capture queue](./capture-queue.mdx) saves job descriptions before resume work. Ask Claude to process that queue later: it compares shared requirements first, asks once about shared gaps, and can reuse a confirmed master correction across relevant drafts. Capture itself never invokes an AI provider or edits a resume.

After changing source, compile again before downloading from the editor. A successful PDF from an earlier source revision is not offered as the current download. Inspect the rendered PDF after tailoring: changed content can change wrapping and pagination.

When you have a specific page target, supply that expected page count before compiling. The checks report the actual count and whether it matches. Overfull box warnings identify possible text overflow; they do not detect every layout problem. Text extraction reports success, empty output, failure or unavailable tools, and gives a bounded text preview. Missing diagnostics from an older worker are shown as unavailable rather than passing. A successful compilation or readable extracted text does not establish ATS compatibility.

Use Documents' existing copy-for-a-job action to create a tailored resume linked to an application. History can show and restore a previous source version. Recording an application as submitted and attaching the version actually sent remains a separate action.

## Connect Claude Code

Connect Claude Code to your local installation rather than the hosted Reactive Resume service:

```sh
claude mcp add --transport http reactive-resume-local --scope user http://localhost:3000/mcp
claude
```

Use `/mcp` to complete browser authentication against the local account. An already-installed Claude client may have different connection controls; use its HTTP MCP setup for this endpoint. A cloud-hosted connector cannot reach your computer's `localhost` without an additional connection mechanism.

Give Claude your background files and job description. Ask it to:

1. Find the master and useful related versions with `find_related_resumes`, then inspect their full content with `read_resume`. Read `read_resume_metadata` for earlier requirement evidence, change rationale and reported outcomes; prioritize relevant verified facts over an earlier score or hiring result.
2. Duplicate the selected base with `duplicate_resume`, preserving the original. Save the posting's requirements and real supporting quotes in `profile.requirementEvidence` through `update_resume_metadata`.
3. Read the `latex` project and use `apply_resume_patch` to edit the appropriate `/latex/files/{index}/content` fields. Preserve the template's formatting commands and supporting files, and record useful before/after excerpts in `profile.tailoringChanges`.
4. Use `compare_resumes` for actual saved-source differences. Its default source is current content, not an automatic historical snapshot; select an existing `sourceVersionId` when that is the intended baseline. Report coarse or truncated comparisons.
5. Run `compile_resume_latex`, optionally with `expectedPageCount` when you specified a target. Review its compiler log and `checks` for page count, overflow and recovered text. `checks: null` and a `diagnosticsNote` mean those checks were unavailable. Fix errors, inspect the PDF where supported, then request `download_resume_pdf`.
6. Save the final requirement map, rationale, score and current review snapshots, and associate the tailored copy with the relevant saved application. Create or update the company's Companies document with `save_company_note` as useful research accumulates. Return the PDF for your review; do not submit or invent an outcome.

These operations do not call Reactive Resume's AI provider. The existing `tailor_resume_for_application` action is a different, provider-backed operation and does not tailor the LaTeX source. External assistants must use the general document editing tools described above.

The compiler's availability can be checked with `api_resume_latex_status`. `api_resume_latex_unpack` converts a base64 source ZIP into the project structure without saving a resume. For an initial import, the browser UI is usually easier. The `tailor_resume_for_job` prompt covers the complete evidence, company research, review and scoring process described in [Organize resumes and company research](./organizing-resumes.mdx).

For captured batches, use `process_tailoring_queue` instead. It claims jobs, resumes existing drafts with retry-safe copy-for-job behavior, persists unresolved shared questions, and marks Ready only after explicit preparation/review. Creating a copied base does not finish the job or mark it Applied. The capture-only extension API key cannot read resumes or process this workflow; use Claude's normal authenticated MCP connection.

## Supported projects and limits

The initial compiler supports PDFLaTeX, with two passes for links and cross-references. It supports `.tex`, common LaTeX style/class/configuration files, image assets, Type 1 font support files, and bibliography source/output files. It does not run BibTeX, Biber, MakeIndex, latexmk configuration, or uploaded scripts. Include a generated `.bbl` when your document needs one. XeLaTeX and LuaLaTeX projects need another compiler implementation.

Limits: 100 project files, 2 MiB per file, 8 MiB for the total decoded project or uploaded source ZIP, and 30 seconds per compilation. Paths must be relative, without hidden files, parent directories, symlinks, or the reserved `rr-build` directory. Unsupported files such as `.latexmkrc` are omitted when importing a ZIP.

PDF and source exports preserve the LaTeX workflow. JSON exports also preserve the project. DOCX, ODT, and Markdown exports are unavailable for LaTeX documents because converting arbitrary TeX would discard formatting or content. Structured-field analysis and provider-backed tailoring do not understand the source automatically; an external assistant should read the source and compiled output.

Public links serve the compiled PDF. Source comments and bundled project files are not included in public resume responses. Keep master resumes private if their rendered contents should not be shared.

## Matching Overleaf's output

Preserving the source does not guarantee identical page breaks across TeX distributions. Compare the compiler and package versions with your Overleaf project. The default worker installs Debian's TeX packages; it is not a pinned copy of Overleaf's environment.

For installations requiring the same typesetting environment, set `LATEX_BASE_IMAGE` in `.env` to a trusted, pinned Debian-based TeX Live image matching that environment, then rebuild the compiler. If the image already provides PDFLaTeX, the worker keeps its installed TeX distribution. Custom images must provide the required fonts and packages; the running compiler does not download them.

## Developer checks

With PDFLaTeX installed, the worker tests run independently of the application:

```sh
python3 -m unittest discover -s containers/latex -p test_worker.py -v
```

For application checks, install the repository's Node/pnpm prerequisites and run its normal typecheck, lint, format, and build commands. Focused regression tests cover source round trips, unsafe paths, imports, compiler errors, public-source redaction, and MCP compilation. Use a disposable local account/database for browser verification.
